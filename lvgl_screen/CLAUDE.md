# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

ESP-IDF firmware for an **ESP32-P4** board (Waveshare ESP32-P4 platform, 1280x800 MIPI-DSI LCD with GT911 touch) running **LVGL v9**. It started as Waveshare's `14_lvgl_demo_v9` example (the CMake project name is still `lvgl_demo_v9`) and is being turned into a custom GUI (engineering thesis project) designed in **EEZ Studio**.

## Build / flash

Requires ESP-IDF (VS Code config points at `C:\esp\v5.5.5\esp-idf`), target `esp32p4`, serial port `COM3`. Run from an ESP-IDF shell:

```bash
idf.py set-target esp32p4     # first time only; regenerates sdkconfig from sdkconfig.defaults
idf.py build
idf.py -p COM3 flash monitor
idf.py menuconfig             # LVGL / BSP / PSRAM options
```

There are no tests or linters. `managed_components/` is populated by the IDF Component Manager from `main/idf_component.yml` and `components/bsp_extra/idf_component.yml` (pinned in `dependencies.lock`) — don't edit it by hand. Settings meant to persist go in `sdkconfig.defaults` (delete `sdkconfig` and rebuild to apply).

## Architecture

- `main/main.c` — `app_main()` starts the display via the Waveshare BSP (`bsp_display_start_with_config`, using `esp_lvgl_adapter`), turns on the backlight, then builds the UI inside `bsp_display_lock(-1)` / `bsp_display_unlock()`. **Any LVGL call from outside the LVGL task must be wrapped in this lock.** It currently still calls `lv_demo_widgets()`.
- `main/CMakeLists.txt` — registers **only `main.c` plus the LVGL demo sources** (globbed from `managed_components/lvgl__lvgl/demos`). The `main/ui/` folder is **not compiled yet**: to switch to the custom GUI, add `ui/*.c` to `SRCS` and `ui` to `INCLUDE_DIRS`, call `ui_init()` instead of the demo, and call `ui_tick()` periodically (under the display lock).
- `main/ui/` — **generated by EEZ Studio** from `GUI.eez-project` (destination folder `main\ui`, LVGL 9.5.0, 1280x800, 16bpp, flow support off). Do not hand-edit generated files; change the `.eez-project` and regenerate. Screens: `SCREEN_ID_MAIN` (wallpaper, clock, date, temperature/weather/pressure labels) and `SCREEN_ID_MENU_PAGE`; widgets are reachable via the global `objects` struct (`screens.h`).
  - The generated code declares symbols the application must implement itself (no implementations exist yet): `action_action_main_gesture(lv_event_t*)` (`actions.h`, gesture handler on the main screen) and `get_var_/set_var_` for `temperature`, `pressure`, `weather` (`vars.h`, `const char*` native variables). Put these in non-generated source files.
  - `ui_image_wp_test.c` is the embedded wallpaper bitmap (large generated array).
- `components/bsp_extra/` — local component layered on top of `waveshare/esp32_p4_platform`: audio codec/I2S helpers, backlight limits, audio player + file iterator.
- `partitions.csv` — 16 MB flash: 8 MB factory app, 7 MB `storage` (SPIFFS).

## Notes

- PSRAM (200 MHz, XIP) is required; LVGL uses the C library malloc/string/sprintf and the FreeRTOS OS layer with 2 SW draw units.
- Enabled Montserrat font sizes are 12–26 (even sizes); a font used in EEZ Studio that isn't enabled in `sdkconfig.defaults` (or embedded by EEZ) will fail to link.
- Using the triple-buffer anti-tearing mode (`tear_avoid_mode`) on IDF 5.5 needs an IDF patch — see the comment/link in `main/main.c`.
- `.vscode/settings.json` points clangd's `--compile-commands-dir` at a different (original example) project's build folder; update it to `./build` if code navigation is wrong.
